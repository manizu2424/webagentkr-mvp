- 작성일: 2026-09-20
- 상태: 사용자 승인 완료(브레인스토밍), 구현 계획 작성 전
- 관련: `task.md` Phase 4, `docs/superpowers/plans/2026-09-09-marketing-redesign.md`(기존 계획 — 본 문서가 방향을 갱신), `CLAUDE.md` 절대 원칙(§0)

## 배경

실배포 후 사용자가 요청한 4건:

1. 진단 결과 화면에 저장 버튼 — 클릭 즉시 PDF 다운로드
2. 자동화 사례 메뉴를 지금은 숨기고, 실제 사례가 생기면 다시 켤 수 있게 로직 유지
3. 사이트 디자인이 단순하다 — 더 멋있게. "라이트 전용" 제약 없이 자유롭게
4. 사이트 구성·내용이 모호하다 — 쉬운 표현으로 단순화

3·4는 미머지 브랜치 `feat/marketing-redesign`(기존 계획 13태스크 중 Task 1~5 완료)과 겹친다. 본 문서가 그 계획의 방향(라이트 전용, 10섹션)을 대체한다.

## Y. 결과 PDF 저장

### 동작
- `GET /api/diagnoses/[id]/pdf` — 서버가 PDF를 생성해 `Content-Disposition: attachment`로 응답. 클릭 즉시 다운로드.
- 상태별 응답: `COMPLETED` → 200 PDF / 그 외 상태 → 409 / 없는 ID·비-uuid → 404. `SUBMITTED`는 `PROCESSING`과 동일 취급(409).
- 결과 카드 화면(`ResultCards`)에 "결과 PDF로 저장" 링크(`<a href=".../pdf">`)를 둔다. FAILED/timeout 화면에는 두지 않는다.
- 파일명: `webagent-진단결과-<진단 ID 앞 8자>.pdf` (`Content-Disposition`의 `filename*=UTF-8''` 인코딩 사용).

### 데이터·PII 경계
- 데이터는 결과 페이지가 쓰는 `lib/diagnosisResult.ts`의 `toApiResult`를 그대로 재사용한다(AI↔DB↔API 매핑 단일 소스 유지).
- **이름·전화·이메일·회사명은 넣지 않는다.** `GET /api/diagnoses/[id]`와 동일한 공개 범위(진단 ID를 아는 사람만).
- 접근 제어는 결과 페이지와 동일: 인증 없음, UUID가 비밀 역할.

### PDF 내용
1. 제목("자동화 진단 결과"), 진단일(KST — `lib/kst.ts` 재사용)
2. 자동화 점수
3. 우선 업무(`priorityTasks`, 업무별 난이도 포함)
4. 절감 시간 — **"추정치"를 표기**, 보장 표현 금지(§0 원칙 4)
5. 추천 스택, 실행 단계 — 빈 배열이면 결과 페이지와 동일하게 섹션 생략
6. 요약
7. 하단 고지: "본 결과는 입력하신 내용을 바탕으로 한 AI 추정치이며 실제 효과를 보장하지 않습니다." + 결과 페이지 URL

### 구현 결정
- 라이브러리: `@react-pdf/renderer`. 폰트: Noto Sans KR(SIL OFL 1.1) Regular·Bold를 저장소에 포함(`assets/fonts/`). 라이선스 고지 파일 동봉.
- 라우트 런타임은 Node.js(`export const runtime = "nodejs"`).
- **Docker standalone**: 폰트 파일은 import 그래프에 없으므로 `next.config.ts`의 `outputFileTracingIncludes`로 명시해 이미지에 실리게 한다.
- 폰트 파일 크기는 서브셋 없이 전체(수 MB)를 사용한다. 서브셋팅은 YAGNI — 크기가 문제로 확인되면 후속.
- **스파이크(계획의 첫 태스크)**: `@react-pdf/renderer`가 Next 16.3 / React 19.2에서 서버 렌더링되는지, 한글이 깨지지 않는지 최소 코드로 먼저 검증. 실패 시 `pdfkit`으로 대체(본 스펙의 나머지는 그대로 유효).
- PDF 문서 컴포넌트는 `lib/pdf/` (또는 `components/diagnosis/pdf/`)에 두고 라우트는 얇게 유지: 조회 → `toApiResult` → 렌더 → 응답.

### 보호·계측
- Rate limit: `lib/rateLimit.ts` 재사용, 키 `pdf:${ip}`, IP당 시간당 20건 → 429. IP는 `lib/clientIp.ts`(결함 #2 준수).
- GA4: `result_pdf_download` 이벤트(`track()`, 링크 클릭 시). 동의 가드는 기존 `track()`이 처리.

### 검증
- `tsc`·`eslint`·`next build` 0.
- 실 Supabase(서울)의 COMPLETED 진단으로 다운로드 → `pdftotext`로 한글·수치·고지 문구 확인, 내부에 PII 문자열 없음 확인.
- 409(PROCESSING), 404(없는 uuid·비-uuid), 429(21번째) 확인.
- `docker build` 후 컨테이너에서 PDF 생성(폰트 로드 확인).

## X. 마케팅 개편

### 디자인
- **방향 A(딥 잉크 히어로 + 밝은 본문)** 확정. 브랜드 토큰(`--wak-*`: ink `#16292b`, signal `#1f3ce6`, resolved `#0c8b77`, paper `#f5f6f2`)은 유지.
- 히어로: 어두운 청록 배경 + signal 블루 라디얼 글로우 + 빛나는 흐름선(노드 3개). 본문 섹션은 밝은 바탕.
- 섹션은 `SectionBand`의 `surface` 속성으로 어두움/밝음을 선택한다. 마지막 CTA 밴드는 어둡게 해 히어로와 짝을 이룬다.
- "라이트 전용" 제약을 제거한다. 별도 다크모드 토글·`prefers-color-scheme` 대응은 **만들지 않는다**(사용자 확인: 디자인이 라이트에 갇히지 말라는 뜻).
- 어두운 표면 위 텍스트·링크·포커스 링 대비를 확보한다(WCAG AA). 어두운 표면용 토큰(`--wak-deep*` 등)을 추가한다.
- 이미 만든 Task 1~5 결과물(SectionBand·아이콘·히어로·문제·서비스·Before/After)은 새 방향에 맞게 조정한다.

### 구성 (10 → 7섹션)

| # | 섹션 | 내용 | 비고 |
|---|---|---|---|
| 1 | 히어로 | "반복 업무, AI가 대신합니다" + 무료 진단 버튼 | 신뢰 요소(무료·약 3분·가입 없음)를 칩으로 흡수 |
| 2 | 이런 고민 있으시죠? | 고민 3가지 → 해결 후 모습 | 문제 + Before/After **통합** |
| 3 | 이런 걸 해드려요 | 서비스 5종, 이름 + 쉬운 한 줄 설명 | 5종 고정(§0 원칙 2) |
| 4 | 이렇게 진행돼요 | 진단 → 제안 → 구축, 3단계 | 절차 단순화 |
| 5 | 자동화 데모 | 데모 3개, `자동화 데모` 배지 | 배지 필수(§0 원칙 3) |
| 6 | 자주 묻는 질문 | 5개 안팎 | 신뢰 요소 흡수 |
| 7 | 마지막 CTA | 무료 진단 시작 | 중간 진단 CTA 삭제, 딥 잉크 밴드 |

### 카피
- 문구는 `content/marketing.ts` 한 곳에서 관리(기존 단일 소스 유지·개정).
- 원칙: 짧은 문장, 전문용어(n8n·워크플로우 등)는 풀어 쓰기, 서비스 이름은 유지하되 이름 아래 쉬운 설명 병기.
- 절대 원칙: "홈페이지 제작"을 서비스로 전면에 내세우지 않는다 / 서비스는 정확히 5종 / 데모는 `자동화 데모` 표시 / 효과 수치는 추정치 표기.
- 확정 전 문구는 `[확정 필요]`로 남기지 않고 실제 문구로 채운다(기존 `TODO` 플레이스홀더 제거).

### 사례 메뉴 플래그
- `lib/features.ts`에 `export const CASES_ENABLED = false`.
- `false`일 때: 헤더 네비에서 제외, 히어로의 "자동화 사례 보기" 버튼 제외, `app/sitemap.ts`에서 제외, `/cases` 직접 접근 시 `notFound()`. 푸터 등 다른 진입점도 같은 상수로 게이트한다.
- `true`로 바꾸고 재배포하면 복구. 사례 상세 구현(task 4.2)은 별개 작업으로 남는다.
- 환경변수를 쓰지 않는 이유: `NEXT_PUBLIC_*`은 빌드 시점에 고정되어 Docker build args 누락 시 조용히 무효화된다(PR #19 사례). 사례 채우기는 어차피 코드 배포가 필요하다.
- `/cases`의 `noindex`는 유지한다(플래그를 켜는 시점에 함께 해제).

### 검증
- `tsc`·`eslint`·`next build` 0.
- Playwright: 데스크톱·모바일(≈400px) 스크린샷, 7섹션 순서, 어두운 표면 대비, 진단·상담 CTA 링크 동작.
- 플래그 on/off 각각에서 네비·히어로 버튼·사이트맵·`/cases`(404 vs 200) 확인.
- 카피 검수: "홈페이지 제작" 전면 노출 없음, 서비스 5종 정확, 데모 배지, 추정치 표기.
